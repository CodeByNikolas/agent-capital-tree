# MultiBaas history adapter

Server-only, read-only Sepolia activity client. Construct it with an explicit HTTPS MultiBaas deployment origin, a View-Only Administrators API key from the server's secret source, the registered controller address, and its MultiBaas contract label. The key is sent only as `Authorization: Bearer …`; it is never returned or included in errors.

`getCapitalActivity(rootId, cursor)` posts a controller-address- and root-filtered Event Query to `/api/v0/queries`. The SDK's EventQuery rows do not include a log index, so each returned transaction hash is enriched through the read-only `/api/v0/chains/ethereum/transactions/receipt/{hash}` endpoint. Results use `chainId:txHash:logIndex` identity and sort by block, transaction, then log index. The receipt is ABI-decoded and bound to the query row’s transaction hash, block number and block hash. `indexed: true` identifies an index-selected transaction/signature/root; the individual log index and financial values come from its receipt. A page includes all matching logs of each selected signature/root in its selected transactions, so adjacent pages may overlap; use `mergeActivityPages` to deduplicate them. Start a new page window on refresh, replacing the old window so orphaned events disappear. Cursors are root-bound and use the Event Query's offset/limit. Indexing and chain status are fetched from MultiBaas on every page; any failed or malformed request fails the call. There is no RPC or synthetic-history fallback.

The map covers eight capital-core events plus `SwapExecuted`, `PositionOpened`, `PositionIncreased`, `FeesCollected`, and `PositionClosed`. Raw integer amounts and NFT IDs are preserved. LP funding amounts are net vault spending because accrued fees can offset inputs; they are not gross principal or PnL. With `rpcUrl`, each page is reconciled against canonical Sepolia blocks and decoded controller receipts: event identity, root and every financial value must agree. Orphaned entries are removed, RPC failures remain errors, and confirmation/finality are explicit. Without `rpcUrl`, finality remains `not_verified`.

Before a live call, MultiBaas must have the controller ABI registered, the deployed controller linked under the configured label, event indexing enabled from a declared coverage start block, and a View-Only Administrators API key with Event Query/read access. The live instance is now linked as `capitalcontroller`, version `1.0`, with indexing from block11783944. Seven positive Root9 setup events passed query/receipt/canonical-RPC comparison after a local fork rehearsal. The separate master-model and published-UI acceptance results are tracked in STATUS.md. Root5 predates this boundary, so its empty response does not mean it had no activity. The free plan permits only100 blocks of lookback; see [plan limits](../../docs/multibaas-plan-limits.md).

Offset pages are provisional indexer snapshots. Changes to indexed history can shift offsets; restart pagination from the first page when refreshing. Use the verified mode and current onchain state before decisions; the indexer is never an authorization source.

Wire fields were verified against the [official MultiBaas TypeScript API](https://github.com/curvegrid/multibaas-sdk-typescript/blob/main/api.ts). Requests reject redirects; only the event emitter must be the controller, allowing smart-wallet transaction targets.

The live API requires the selected `blockNumber` alias for `orderBy`; ordering by its field type `block_number` returns HTTP400. DApp User alone can execute queries but receives HTTP403 for indexing status. The derived runtime key therefore also has View-Only Administrators membership (read-only metadata access, no edit or Web3 roles). The original setup administrator key is kept locally and is not deployed to Vercel.

Live Event Query block numbers arrive as decimal strings; values are checked for safe integer conversion. Financial uint256 values remain exact strings. This free-plan instance returns an empty `/events` log store while its indexed queries and transaction receipts work. Its status checkpoint can also trail events already returned by queries; we expose the reported checkpoint without claiming a complete up-to-head history. Agent decisions must use positive verified events plus fresh balances, capabilities and position state, not infer inactivity from missing events.
